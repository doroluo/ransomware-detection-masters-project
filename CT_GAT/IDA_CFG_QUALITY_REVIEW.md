# Dataset-quality review and revised extraction policy

The research dataset should preserve reusable static evidence. Architecture
limits belong in model preprocessing, not in the permanent extraction dataset.
The first exporter was unnecessarily restrictive for this purpose.

## Feature retention

| Evidence | Revised policy | ML interpretation |
|---|---|---|
| Instructions | Retain all recovered function instructions, raw IDA mnemonics, instruction sizes, ordered block membership | Tokenize/normalize in separately versioned training views |
| Addresses | Retain RVAs, function chunks, block bounds, instruction offsets; image base is metadata | Use relative relationships; avoid feeding absolute load addresses as numeric features |
| Operands | Keep register names, data types/widths, immediate values, displacement values, target RVAs, phrase IDs and processor flags | Preserve raw structured values; learn/evaluate normalized or bucketed views later |
| API/import/export names | Retain names, ordinals, DLLs, delayed imports and instruction references to imports | Separate imported APIs from statically referenced APIs; neither proves runtime use |
| Function/symbol names | Retain names and library/thunk flags | Exclude autogenerated names and provenance/debug names by default in model views; ablate named-symbol features |
| Strings | Retain escaped text with encoding and RVA/file offset, including resource/overlay strings | Treat as data; normalize paths/URLs and evaluate whether family identifiers or build paths cause shortcuts |
| PE structure | Retain sections, sizes, permissions, entropy, entry point, machine, subsystem, DLL flag and timestamp | Timestamp is untrusted provenance, not a reliable collection date |
| Bytes | Retain a 256-bin byte histogram; original bytes remain in the VM, keyed by SHA-256 | Histogram is not equivalent to raw-byte input; raw-byte models need a separate VM-side feature/training workflow |
| Full assembly | Do not export a separate full listing by default | Structured instructions are the working representation; the access guide separately requires approval for full-listing transfer |
| Labels and source paths | Preserve in sidecars with original cohort rows and label evidence | Never insert corpus, family labels, file names, original split or AV tags into graph features |

Raw symbols and strings are intentionally available for research, not a claim
that every retained field should be fed to every model. Imported API names are
usually more defensible than sample-specific symbol names. Compare feature
ablations on held-out sources/families rather than assuming more fields improve
generalization. EMBER demonstrates the useful distinction between stored raw
static features and downstream vectorization: https://github.com/elastic/ember

## Runtime and completeness restrictions

| Previous setting | Revised setting | Reason |
|---|---|---|
| 50,000 blocks / 1,000,000 instructions | No extraction count caps | Address-prefix cuts can discard core behavior and systematically affect larger programs |
| Whole-sample graph accumulated in RAM | Gzip JSONL, one function at a time, plus separate string/orphan records | Avoid retaining every recovered function in memory; the largest individual function still consumes memory |
| 2,500 MiB virtual-address-space limit | No `RLIMIT_AS`; watch actual process-tree RSS, default 6,144 MiB, and guest available RAM | Virtual mappings are not resident memory; preserve about 2 GiB for the OS/controller on an 8 GiB guest |
| 1.5 GiB file-size limit | Removed | Do not reject a graph solely because its serialized artifact is large |
| 300-second timeout | 3,600-second first attempt; 14,400-second retry for timeout/memory/SIGKILL cases | More time for large or difficult samples; retain finite limits for hangs |
| Two simultaneous IDA workers | One | Spend the small VM's RAM on one complete analysis |
| Existing failures skipped permanently | Explicit retry support and per-attempt history | `--retry-failures --timeout ... --retry-timeout ...` permits deliberate escalation |
| Empty graph considered the only output failure | Preserve PE/string/byte evidence and mark `no_function_instructions` | A sample with no function CFG should not disappear from the ML denominator |
| Managed/non-native samples dropped from feature extraction | Separate metadata-only track | Native PE CFGs do not substitute for CIL CFGs; unsupported graph backends remain explicit |
| External function-flow targets omitted | Retain IDA external placeholder blocks and edges | Keep boundary relationships without pretending external placeholders are analyzed blocks |
| Instructions outside functions omitted | Export IDA-recognized orphan instructions separately | Retain recognized evidence without inventing CFG edges |
| Whole corpus retained on the VM before transfer | Transfer after 100 artifacts or about 256 MiB, then free only acknowledged derived copies | The VM's 18 GiB free disk must not silently bound corpus size |
| Broad archive copy | Explicit file-name allowlist, package and artifact hashes, streaming schema validation | Preserve isolation and integrity while allowing richer data |

The numeric RAM/time thresholds are engineering starting points for this VM,
not scientifically validated acceptance thresholds. Pilot timing cannot predict
the full corpus. Record peak RSS and per-attempt time, examine failures by label,
source, architecture, packing indicators and size, then increase budgets where
evidence warrants it. A sample that still cannot fit the 8 GiB guest remains a
reported failure; it needs stronger analysis resources, not a secretly cut graph.

The memory guard polls, so it cannot guarantee prevention of every transient
allocation spike or kernel OOM. Worker-reported peak RSS supplements polling.
The 3 GiB VM disk reserve and desktop free-space checks are retained. Packages
have no arbitrary 128 MiB member-size ceiling. Derived VM artifacts are removed
only after the desktop has verified the package and every graph and acknowledged
the exact package hash. Original samples and analysis histories are never deleted.

## Remaining scientific limits

- IDA auto-analysis completion means its analysis queues finished, not that the
  actual program CFG is complete. Record recognized code counts, orphan code,
  failed instruction decodes, unresolved calls and external placeholders.
- Packed/obfuscated files may yield mostly loader stubs. Preserve packing hints
  through section names/entropy and cohort tags. A later **static** unpacking
  experiment should produce a separately hashed derived view and link it to the
  original. This implementation does not run UPX or execute samples.
- Managed code remains a separate metadata track until a CIL-aware CFG backend
  is validated. Do not treat its native loader stub as a complete managed CFG.
- Strings use a documented minimum length of four. The file scan covers ASCII
  and UTF-16LE printable strings, supplemented by IDA's recognized strings.
  This is not a promise to recover encrypted strings, every encoding, or every
  runtime-constructed API name. Duplicate file/IDA string views remain identifiable.
- The graph retains IDA's recovered successors and code/data references. It does
  not add speculative branch labels, resolve all indirect calls or claim dynamic
  behavior. Shared function tails can produce repeated instruction occurrences;
  unique IDA code counts are recorded separately.
- Byte histograms cannot train an arbitrary raw-byte CNN. Full samples remain
  available in the VM for future authorized feature extraction. No sample or
  equivalent raw byte dump is moved to the desktop.

## Dataset and evaluation controls

Keep original Mendeley assignments immutable as provenance. Store new experiment
split manifests separately, with hashes, architecture, inclusion criteria,
random seed and feature-view version. Retain excluded files and exclusion reasons.
Labels are sidecars, never graph inputs. VirusShare `is_ransomware=0` is not a
benign label; its full source labels (including engine counts and tags) are saved
in `source_labels.json` for confidence review.

Exact-hash overlap and label conflicts are already audited. Also evaluate near
duplicates, repacks and shared families before reporting model accuracy; exact
SHA-256 deduplication alone does not eliminate leakage. Use source-held-out and
family-held-out tests where appropriate. Use temporal tests only when trustworthy
collection timestamps exist; PE timestamps are forgeable. These controls matter
at least as much as feature richness. See TESSERACT's treatment of spatial and
temporal evaluation bias: https://www.usenix.org/conference/usenixsecurity19/presentation/pendlebury

For GNNs or transformers, apply graph sampling, sequence length limits, vocabulary
fitting and normalization at training time, save the configuration, and compare
coverage across labels. Preserve the full extracted data so those choices can be
revisited without another IDA pass.

## Implementation and operation

- `extract_cfg_with_ida.py`: IDAPython extraction and streaming validator; current
  schema `ida-cfg-research/2.1`. Header records include extractor SHA-256, IDA
  version and analysis flags. No instruction/block truncation is performed.
- `run_research_cfg.py`: single-worker controller, retries, resource monitoring,
  grouping manifests, batch packaging, desktop receiving and acknowledgments.
- `test_research_cfg.py`: schema, incomplete-file, path, grouping, memory-retry
  and acknowledged-cleanup regression checks.

VM output root: `/home/seed/work/out/ida_cfg_quality_20261006/`.
Windows output root: `reports/ida_cfg_quality_20261006/` in the repository.
The revised full run uses `full/` underneath these roots. Old pilot artifacts
remain under the original dated root and are not mixed into the revised dataset.
The first richer compatibility pilot used draft schema 2; final-schema pilots
and the full run use 2.1 and are kept in separate folders.

Each sample's `features/<sha256>.jsonl.gz` contains a header, function records,
optional orphan records, string records and a validated completion footer.
Group/class/split/family directories contain hard links to canonical artifacts
where supported. `manifest.csv`, `mendeley_samples.csv`, original cohort rows,
labels, per-sample status and receipts remain accessible on the desktop.

An output's `complete=true` means the configured static extractor completed
without intentional graph truncation; inspect `graph_status` and the static
limitations. It does not mean unpacking, CIL recovery or runtime behavior is complete.

The receiver waits for up to 30 days and stops on persistent connection errors
or explicit pipeline errors. Keep the VM and desktop on. Interrupted transfers
can be resumed using the same policy/extractor; an extractor change requires a
new output directory to avoid mixing incompatible representations.

## Verified dataset identity findings

The completed inventory contains 44,689 files and 44,677 unique hashes. Three
dataset support files are excluded from analysis, leaving 44,674 unique inputs
for the revised native-CFG/metadata extraction tracks. There are 717 managed PE
file occurrences, which retain metadata instead of being silently dropped.

All 2,675 Mendeley file records and original folder splits are preserved. Of
these, 96 have no exact SHA-256 match in the cohort CSV: 69 goodware train, two
goodware test, 16 ransomware train and nine ransomware test. Each has one
same-name/split candidate in the previous extraction manifest, but every file
differs in both SHA-256 and size. Rehashing confirmed all 96 current inventory
identities. Simple LF/CRLF transformations did not match the old hashes. This
does not establish why the files differ. Do not import cohort inclusion flags
or claim exact cohort membership based only on filenames.

**Resolved by exact transformation proof:** a subsequent static UPX audit
unpacked private copies of all 96 files inside the VM. Every unpacked SHA-256
matched its expected cohort SHA-256 exactly. The current files are packed
representations of the cohort content. No original was changed or executed,
and no unpacked sample was transferred to Windows. The original raw SHA-256
remains the feature-file key; `cohort_sha256` records the verified unpacked alias.
The previous warning against filename-only matching remains valid, but these
96 identities are now proven through content hashes rather than filenames.

The read-only report is
`reports/ida_cfg_quality_20261006/mendeley_identity_audit.json`; it records old
hashes/sizes, current hashes/sizes, architectures, original splits and the
filename candidates and exact UPX verification results. No sample or original
identity/label field was rewritten.

There are no exact-hash label conflicts in the inventory. One exact hash occurs
across training/test assignments:
`a9503a3d998e705c37d3bec7fea0ff188bcf7e753833c8b4b195e590c4ed9625`.
It occurs in Mendeley `mal_test` and VS `mal_train`. The corrected experiment
manifests reserve its identity for test and exclude the VS training occurrence.
The same rule applies across every verified packed/unpacked identity component,
not just byte-identical hashes. Near-duplicate/family leakage remains unaudited.

### Reconciled experiment manifests

Use `reports/ida_cfg_quality_20261006/full/reconciliation/` for new experiments.
The original root manifests, CSV memberships and folder splits remain unchanged.

- `samples.csv`: every original file, effective identity/split, eligibility and
  explicit exclusion reason. `current_representation` distinguishes packed
  inputs; `matched_cohort_tag` describes the matched cohort representation and
  must not be mistaken for the representation used for the current CFG.
- `mendeley_samples.csv`: all 2,675 Mendeley files, with 2,579 exact-hash matches
  and 96 verified UPX-transform matches. No Mendeley identity is unresolved.
- `identity_aliases.csv`: current SHA-256 to verified cohort SHA-256 mappings.
- `train.csv` / `test.csv`: 5,280 training and 486 test identities selected from
  the existing cohort-included pools, deduplicated globally and with zero exact
  or verified-transform identity overlap. Mendeley is preferred as the source
  row when an eligible identity has multiple occurrences in the same split.
- `train_ready.csv` / `test_ready.csv`: the selected identities whose artifacts
  have actually arrived and validated. These refresh after each desktop batch.
  They are partial until extraction finishes, not a complete evaluation pool.
  Check `graph_status` as well: artifact readiness does not imply a native CFG.
- `excluded.csv`: original exclusions, duplicates reserved for test, unverified
  memberships and samples without a defined experiment split. Features remain
  available for all these samples in the overall extraction dataset.
- `report.json`: policy version, evidence hash, exclusion counts and overlap checks.

VirusShare has no supplied experiment split, so its 38,157 records remain in
the extraction dataset but are not silently assigned to either default split.
The 28 remaining unmatched memberships are outside Mendeley and are retained
with an explicit exclusion from the default cohort-defined experiment pool.
This is an experiment eligibility policy, not removal from feature extraction.

`reconcile_cfg_dataset.py` regenerates these manifests deterministically.
The desktop receiver invokes it after each batch when `identity_evidence.json`
exists. Six additional tests verify hash-transform resolution, cross-source
leakage, packed/unpacked leakage, original exclusions, and readiness updates on
both Windows and Python 3.8. A VM-side snapshot is also saved, but ready counts
are authoritative on the desktop because acknowledged artifacts leave VM storage.

## Current validation evidence

Eight revised-pipeline regression tests pass on Windows and VM Python 3.8,
including memory-pressure retries and acknowledgement-gated cleanup. The final
schema pilots produced 24 transferred artifacts: 14 with recovered native CFGs,
nine managed metadata-only artifacts, and one native sample with no recovered
function instructions but retained static features. There were no extraction
process failures in these final-schema pilots. Pilot results do not establish
full-corpus coverage or static-analysis completeness.

The revised full run is active under `nohup`; the desktop receiver transfers and
validates batches automatically. Consult VM `full/pipeline_state.json` and the
desktop `full/transfer_status.json`, `summary.json`, and `receipts/` for current
counts. A running job or completed pilot does not mean the full dataset is done.

The first full-run batch of 100 artifacts passed desktop schema/checksum
validation and the VM acknowledged-transfer cleanup, after which extraction
resumed. All 100 have recovered native CFGs. Their maximum graph sizes were
42,967 blocks and 195,914 instruction occurrences; no count cap was applied.
These are early batch observations, not corpus-wide performance or coverage.
